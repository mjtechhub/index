NetFlow / IPFIX Explained

While Syslog tells you about device events and SNMP tells you interface utilization, Flow Telemetry tells you exactly who is talking to whom on the network.

NetFlow and IPFIX

NetFlow is a flow analysis technology originally developed by Cisco. IPFIX (IP Flow Information Export) is the open, standards-based equivalent derived from NetFlow v9 concepts. They are fundamentally similar but not exactly identical.

How it Works

  • Exporter: A router or switch observes traffic and aggregates it into a "flow record." A flow is conceptually defined by fields like Source IP, Destination IP, Source Port, Destination Port, and Protocol.
  • Collector: A server that receives the exported flow records.
  • Analyzer: The software used to visualize and search the collected data.

Flows vs. Packet Captures

Flow telemetry is metadata/summary information. It tells you that IP A sent 500 MB to IP B on port 443 at 2:00 PM. It does not contain the actual application payload. Conversely, a Packet Capture (PCAP) contains individual frames and payloads. PCAPs are massive and used for deep analysis, while flows are lightweight and used for long-term historical trending.

Use Cases

Because flows track conversations, they are essential for identifying "Top Talkers" (who is causing the bandwidth spike), analyzing traffic patterns for capacity planning, investigating security incidents, and tracking bandwidth usage per application.

Note: On high-speed backbone links, routers often use "Sampled NetFlow," where only 1 in every N packets is inspected to reduce CPU load.
