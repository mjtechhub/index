MTU and MSS Explained

Understanding packet sizing is crucial when dealing with complex routing or VPN overhead.

MTU (Maximum Transmission Unit)

MTU is the largest size (in bytes) that a particular interface can transmit without needing to fragment the packet. The most common standard Ethernet MTU is 1500 bytes, though this is not universally mandatory (e.g., Jumbo Frames support 9000 bytes).

MSS (Maximum Segment Size)

MSS is a TCP concept. It defines the maximum amount of application payload data that a host is willing to accept in a single TCP segment. MSS is calculated during the TCP handshake to prevent IP fragmentation.

The Conceptual Math

For standard Ethernet IPv4 TCP traffic without extra options:

  1500 bytes (MTU)
-   20 bytes (IPv4 Header)
-   20 bytes (TCP Header)
-------------------------
= 1460 bytes (TCP MSS)

This is purely conceptual. Do not give 1460 as a universal value. IPv6 headers are larger (40 bytes), TCP options (like timestamps) reduce available payload, and encapsulation (such as VPN tunnels) will further reduce the effective MTU.

Fragmentation and PMTUD

If a router receives a packet larger than the outbound interface's MTU, it must either fragment it or drop it. IPv4 allows intermediate fragmentation. However, if the packet is marked "Don't Fragment" (DF), the router drops it and is required to send an ICMP "Fragmentation Needed" message back to the source.

Path MTU Discovery (PMTUD) relies on these ICMP messages to dynamically learn the smallest MTU along a path. If strict firewalls block these ICMP messages, PMTUD fails, resulting in a "black-hole" where small pings work, but large data transfers hang.

Testing MTU

You can test path MTU on Windows by forcing the DF bit and specifying a payload size:

ping example.com -f -l 1472

Note: The `-l` value is payload size. 1472 payload + 28 bytes (ICMP/IP headers) = 1500 bytes total packet size on the wire.
