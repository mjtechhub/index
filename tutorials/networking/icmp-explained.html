ICMP Explained

Beginner 5 min read

The Internet Control Message Protocol (ICMP) is a core protocol used by network devices, like routers, to send diagnostic information and error messages regarding network connectivity.

Key Characteristics of ICMP

Unlike application data streams, ICMP is not used to exchange bulk data between systems. More importantly, ICMP does NOT use TCP or UDP port numbers. It sits directly on top of the IP layer (Protocol Number 1), meaning terms like "ICMP port 80" are technically inaccurate.

Common ICMP Message Types

ICMP communicates using specific "Types" and "Codes." The most common are:

  • Echo Request (Type 8) & Echo Reply (Type 0): These are the messages used by the Ping command. A device sends an Echo Request, and the target responds with an Echo Reply if it is reachable.
  • Destination Unreachable (Type 3): Sent by a router when it cannot forward a packet to its final destination (e.g., if there is no route or a firewall blocks it).
  • Time Exceeded (Type 11): Used heavily by Traceroute. It is sent by a router when a packet's Time-To-Live (TTL) hits zero, causing the packet to be dropped.

Diagnostic Tools Using ICMP

Administrators rely on ICMP daily using commands such as:

ping
tracert    (Windows)
traceroute (Linux/macOS)
pathping   (Windows)

ICMP and Firewalls

For security reasons, some administrators completely block all ICMP traffic. While it's true you don't always want your servers responding to random pings from the internet, completely blocking all ICMP can negatively affect diagnostics and break essential network functions (like Path MTU Discovery). It is generally best practice to selectively allow specific ICMP types (like Time Exceeded and Destination Unreachable) while filtering others based on network policy, rather than dropping ICMP entirely.
