Access Control Lists (ACLs) Explained

An Access Control List (ACL) defines rules used to permit or deny traffic passing through a network device according to matching criteria.

Matching Criteria

Depending on the type of ACL and the vendor, rules can filter traffic based on:

  • Source IP address
  • Destination IP address
  • Protocol (e.g., TCP, UDP, ICMP)
  • Source / Destination ports

Standard vs Extended ACLs

Note: This is vendor/platform terminology, heavily used in Cisco environments.

  • Standard ACLs: Typically filter traffic based only on the source IP address.
  • Extended ACLs: Can filter based on source IP, destination IP, protocol, and ports, offering granular control.

Rule Processing and Implicit Deny

ACLs are processed top-down in first-match behavior. Once a packet matches a rule, the action (permit or deny) is applied, and no further rules are checked.

Crucially, almost all ACLs end with an invisible implicit deny rule. If a packet does not match any explicitly configured rule in the list, it is dropped.

Conceptual Example Policy

Rule 1: Permit TCP from 10.10.10.0/24 to 10.20.20.50 eq 443
Rule 2: Deny IP any any (Implicit or explicit)

In this conceptual example, hosts on the 10.10.10.0/24 subnet can access a secure web server at 10.20.20.50. All other traffic is denied. Note that syntax is not universal across vendors; always consult your platform's documentation.
