Access Port vs Trunk Port

In a network environment utilizing VLANs, switch ports generally operate in one of two main modes: Access or Trunk. Understanding this distinction is essential for deploying switches and connecting devices.

Access Port

An Access Port is configured to carry traffic for only one specific VLAN toward an end device. When a PC or printer connects to the switch, it has no concept of VLAN tags; it just sends standard network frames. The switch assigns that traffic to the configured VLAN internally.

  • Example: Laptop → Access Port → VLAN 20

Trunk Port

A Trunk Port is configured to carry traffic for multiple VLANs simultaneously over a single physical link. To keep the traffic separated as it moves between devices, the switch uses 802.1Q VLAN tagging, adding a special header to the frame indicating which VLAN it belongs to.

Common examples of trunk connections include:

  • Switch ↔ Switch: Passing multiple VLANs between switches.
  • Switch ↔ Firewall/Router: Passing multiple VLANs up to a gateway for routing.
  • Switch ↔ Access Point: When the AP broadcasts multiple Wi-Fi SSIDs mapped to different VLANs (e.g., Guest vs Corporate).

The Native VLAN

A trunk port typically designates one VLAN as the Native VLAN. Any frame belonging to the Native VLAN is sent untagged (without an 802.1Q header). It is crucial that both ends of a trunk link agree on which VLAN is the native one; otherwise, traffic can leak between different subnets.

Comparison Table

Feature Access Port Trunk Port
Supported VLANs Only one VLAN Multiple VLANs
VLAN Tagging (802.1Q) No tags used (untagged frames) Tags frames (except Native VLAN)
Typical Connected Device PCs, printers, IP phones Switches, routers, firewalls, APs

Note: While concepts remain identical, note that different hardware vendors might use slightly different configuration syntax or terminology for tagging and untagging ports.
