Stateful Firewall Explained

A Stateful Firewall inspects traffic and monitors the active connection/session state, allowing it to make intelligent filtering decisions compared to older, stateless packet filters (like simple ACLs).

Stateless vs Stateful Filtering

  • Stateless Filtering: Evaluates every single packet in isolation based on static rules. To allow a client to browse the web, you would need one rule allowing traffic out to port 443, and a separate inbound rule allowing traffic back from port 443 to the client's high random port.
  • Stateful Inspection: Evaluates packets in the context of an established session. If an internal client initiates a TCP connection to a web server, the firewall adds that session to its state table. Return traffic belonging to that exact session is automatically permitted, without needing a completely independent inbound rule.

The Session Table

The firewall maintains a dynamic state table containing information such as:

  • Source and Destination IP
  • Source and Destination Service/Port
  • Protocol
  • Ingress and Egress Interface/Zone
  • TCP connection state (e.g., SYN-SENT, ESTABLISHED)

For UDP, which is inherently stateless, the firewall typically creates a "pseudo-state" tracking the session based on IP and port pairs with a timeout mechanism, depending on the implementation.

Security Distinctions

Do NOT claim all firewalls behave identically; behavior varies heavily by vendor and configuration. Furthermore, do NOT imply HTTPS traffic contents are automatically visible merely because a firewall is stateful. A stateful firewall tracks the TCP connection flow, but the payload inside the HTTPS traffic remains encrypted. Encrypted-traffic inspection (Deep Packet Inspection / SSL Decryption) is a separate advanced concept.
