Network Baseline & Capacity Planning

Effective network monitoring requires context. A baseline provides that context.

What is a Network Baseline?

A baseline is a historical picture of normal network behavior over time. Relevant metrics include bandwidth utilization, latency, interface errors, client counts, CPU/memory usage, and application availability.

A baseline helps you instantly answer the crucial troubleshooting question: "What changed?" If users complain about a slow internet connection, and your monitoring shows WAN utilization at 95%, you need your baseline to know if 95% is a new anomaly or if it's been running at 95% every morning for six months.

Capacity Planning

Capacity planning uses historical baseline data to predict when the network will run out of resources. You must account for current usage, expected organic growth, and business changes (e.g., deploying new video conferencing software, shifting to remote workers, or modifying backup schedules).

Sustained vs. Burst Behavior

Avoid simplistic rules like "upgrade whenever bandwidth exceeds 70%." A network interface hitting 100% utilization for 3 seconds during a file transfer is normal burst behavior. Hitting 100% for 3 hours indicates sustained congestion.

The 95th Percentile

A common concept in capacity planning and ISP billing is the 95th percentile. This discards the top 5% of usage spikes (bursts) and measures the sustained usage level. While highly useful, it is not the only valid planning method; highly latency-sensitive networks may need to engineer for absolute peak bursts to avoid QoS queuing delays.
