Syslog Explained

Syslog is a standardized mechanism used by network devices (firewalls, routers, switches) and servers to send event and log messages to a centralized collector or logging server.

Message Components

A standard syslog message contains several parts:

  • Timestamp: When the event occurred.
  • Hostname / Source: Which device sent it.
  • Facility: The subsystem that generated the log (e.g., kernel, mail, auth).
  • Severity: How critical the event is.
  • Message: The actual log content.

Severity Levels

Syslog uses a numerical severity scale where a lower numerical value indicates a more severe event.

  1. Emergency (0): System is unusable.
  2. Alert (1): Action must be taken immediately.
  3. Critical (2): Critical conditions.
  4. Error (3): Error conditions.
  5. Warning (4): Warning conditions.
  6. Notice (5): Normal but significant condition.
  7. Informational (6): Informational messages.
  8. Debug (7): Debug-level messages.

Transports and Security

Traditional syslog commonly relies on UDP port 514. Because UDP is connectionless, logs can be lost in transit. Some implementations support TCP 514 for reliability. Secure syslog over TLS commonly uses TCP 6514, providing encryption to protect sensitive log data from interception.

Note: Log collection is not full monitoring. Logs complement active SNMP metrics and alerts.
